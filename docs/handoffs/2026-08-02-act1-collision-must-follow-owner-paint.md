# Handoff — Act 1: the collision must be rebuilt from the owner's paint — 2026-08-02

## The headline

**The owner's painted terrain is the authority. The ART already honours it (99.9%). The
COLLISION does not (53%).** Rebuild the collision from the paint. Do not touch the art.

| artefact | agreement with the owner's paint | made |
|---|---|---|
| `art-tiles/act1-smoothed-semantic.png` → the material art | **99.9%** | 30 Jul |
| `public/act1-world-map.js` `ROWS` → what `canMove` enforces | **53.1%** | **15 Jul** |
| `dist/act1-hifi/manifest.json` `semanticRows` | 53.1% (byte-identical to ROWS) | **19 Jul** |

**Owner, verbatim (2026-08-02): "please redo the collision setting based on what i created (my
paint). this shouldn't even be a question."** They are right. Their paint post-dates and
supersedes the generated map, per `2026-07-29-owner-painted-terrain-to-codex-art.md`: *"Their
paint is now the authority for terrain, exactly as their landmark placement is the authority for
placement."*

## How it happened

- **15 Jul** — `act1-world-map.js` generated by `export_act1_runtime_override.mjs` from
  `buildAct1OverworldReconstruction()` + `ACT1_RUNTIME_SNAPSHOT_ROWS` — i.e. from the OLD
  *generated* semantic map, and from a snapshot of the already-shipped runtime.
- **19 Jul** — `act1-hifi` bakes that same topology into `manifest.json`.
- **29 Jul** — the owner rejects the generated map ("the semantic map is a mess") and paints the
  terrain by hand. `owner-terrain.json` / `act1-owner-semantic.png`.
- **30 Jul** — the ART pipeline picks up the paint. **Nothing else does.**
- **31 Jul** — the material art is rendered from the paint, faithfully.

The collision generator was never wired to the paint — it reads a snapshot of the shipped
runtime — so it could not have picked it up. This is also the root cause of the **roads** episode
(2026-08-01): the class-`1` road network lives only in the stale topology; the owner's paint has
**no road cells at all**.

## Verified before any code was written

- **The owner's paint is internally sound.** All 9 Act-1 landmarks stand on open ground
  (`.`), each with 3–4 walkable neighbours, and **all 9 are mutually reachable** in a single
  **16,723-cell** region. Walkable (unpainted `.` + `R`) is 62.2% of the act.
- **Collision alone is NOT enough — it would brick three destinations.** The owner's landmark
  placement and the shipped connection table are different layouts:

  | | owner's paint | shipped runtime |
  |---|---|---|
  | Greenhollow | (69, 255) | (60, 340) |
  | Millbrook | (39, 344) | (100, 320) |
  | Misty Grotto | (91, 378) | (120, 260) |

  Under the owner's terrain the OLD entrance cells for **Millbrook, Misty Grotto and Crystal
  Cave have ZERO walkable neighbours** — unenterable. Collision and entrances must move together.
- **Transitions can be overridden without a build.** `act1-hifi/adapter.js:449` delegates to
  `scene.checkTransition(x,y)` / `scene.performTransition(t)` on the BASE scene, whose connection
  table is frozen in the bundle. But the overlay already monkey-patches `scene.canMove`
  (`wrapCanMove`), so it can patch `checkTransition` the same way. **Confirm `performTransition`'s
  expected object shape from the bundle before relying on this.**

## The work, four coupled pieces (all in the overlay, no build needed)

1. **`ROWS` from the paint.** Map `.`→0, `F`→3, `M`→4, `W`→2. Effective overworld collision is
   the base game's blocked set `{2,4,6,7,8,9,10,11,12,14,15,16,19,20,21}` (read out of the
   bundle's `canMove`) **plus tile 3**, which the base game treats as walkable and the Act-1
   wrapper blocks explicitly. Codes `>=5` are landmark/special cells.
2. **Move the landmark codes** to the owner's placement (`owner-terrain.json` `acts.1.landmarks`,
   world coords).
3. **Patch `checkTransition`** so entrances fire at the owner's coordinates.
4. **Recompute `SAFE`** (relocation candidates) from the owner's landmark approaches; keep
   `GATE`, `HARBOR_CELLS`, `BRIDGE_DECKS`, `FOREST_BLOCK`. Then update the `ACT1_OVERLAY_FILES`
   pin for `act1-world-map.js`, re-copy to `dist/`, and re-run the gates.

Prefer regenerating through `scripts/export_act1_runtime_override.mjs` (add an owner-paint source)
over hand-editing, so `npm run test:map-engine`'s `--check` stays meaningful. Note that changing
the terrain source invalidates what `ACT1_V3_LOCKED_DESIGN_SHA256` asserts — decide deliberately
whether that constant still means anything.

## Gotchas

- **A road layer was built and fully reverted on 08-01.** Act 1 is roadless BY DESIGN (roadless
  base 2026-07-19 → ADR-0069; the owner's paint has no `R` cells). `render_material_map.py` is
  verified byte-identical to before that experiment, and its `LEGEND` now carries a comment
  saying why four classes is intentional. **Do not re-add roads.**
- **My reachability check printed a green "all reachable" while silently excluding the landmarks
  that had NO approach at all.** Any validator here must fail loudly on the empty case.
- **`src/` and `dist/` have diverged and dist is what ships.** dist has no `tryDevStartFromUrl`,
  so `?dev=1&map=overworld` **does not work** — the only route to the overworld is playing out of
  Greenhollow. Read dist for shipped behaviour.
- **Synthetic taps DO reach the game.** The old "WKWebView ignores touch injection" note is false;
  Start Game silently no-ops until Hero Name is non-empty. Read tap coords from
  `xcrun simctl io <udid> screenshot` (true 1206x2622, **tap-point = px / 3**), never from the MCP
  panel screenshot, which is not a uniform scale of the device.
- **The hero can never stand under canopy** — forest is impassable, so occlusion only matters
  where canopy overhangs walkable ground at a treeline.
- **`runtime.html` takes a chunk's source rect from the MANIFEST, not the image.** A higher-res
  chunk dropped in unpatched silently renders its top-left quarter. `bake_act1_chunks.py
  --patch-runtime` fixes it.
- **The owner reviews on a PHONE and file attachments do NOT render there** — they arrive as
  generic "PNG" chips. Resizing does not help; the channel is wrong. **Publish an Artifact URL**
  and build the HTML with a Python script that base64-embeds the images (writing base64 through a
  tool call would cost ~100k tokens). Current review page:
  `https://claude.ai/code/artifact/14d03bc3-ba50-44fa-91b5-3efc8bfc2dfb`
- **Never `nohup … &` inside a `run_in_background` Bash call** — the harness tracks the launcher,
  which exits instantly and reports "completed" while the real job has barely started.
